## 🧭 파인튜닝이란?

> 이미 학습된 모델을, 목적에 맞는 데이터로 **추가 학습**하는 과정

- 사전학습(pre-training)이 끝난 모델의 파라미터에서 **출발**한다.
- 처음부터 새로 배우는 게 아니라 **이미 배운 표현·지식을 재사용**한다.
- 같은 모델이라도 추가 학습에 쓴 데이터에 따라 **응답 방식이 달라진다.**

왜 필요할까? 같은 질문("배송이 너무 늦어요")에도 서비스마다 원하는 답 형식과 톤이 다르다. 일반 모델은 길고 원론적으로 답하기 쉬운데, 우리 서비스는 "사과 + 주문번호 요청, 두 문장"을 원할 수 있다. 프롬프트만으로 이 형식을 매번 지키기 어려울 때, **질문-목표 응답 쌍을 학습 데이터로 삼아 형식·톤을 고정**하는 것이 파인튜닝의 목표다.

기존 ML/DL 파인튜닝과 비교하면 이렇다. (수업에서도 두 대표 예시만 비교한 것이라고 했다.)

| | 이미지 분류 모델 FT | 생성형 LLM SFT |
|---|---|---|
| 공통점 | 사전학습 파라미터에서 시작해 목적 데이터로 추가 학습 | 동일 |
| 입력 | 이미지(고정 크기 배열) | 가변 길이 텍스트(토큰 열) |
| 정답 형식 | 클래스 레이블 | 목표 응답 텍스트 |
| 출력 | 클래스별 확률 | 다음 토큰 확률 분포 → 문장 |
| 평가 | 정확도, F1 등 | 정량 지표 + 형식·톤 같은 사람 판단 |

## 📉 Loss: 틀린 정도를 숫자 하나로

**Loss는 정답 토큰에 준 확률이 낮을수록 커지는 값**이다.

| 정답 토큰의 확률 p | Loss (−ln p) |
|---|---|
| 0.9 | 약 0.105 |
| 0.5 | 약 0.693 |
| 0.1 | 약 2.303 |
| 0.01 | 약 4.605 |

예를 들어 "서울은 대한민국의 [수도]"에서 '수도'에 0.9를 줬으면 loss가 작고, 0.01을 줬으면 크다. 학습 목표는 **전체 데이터의 loss 평균을 낮추는 것**이다.

주의할 점이 있다. loss는 정답률이나 사실성 점수와는 **다른 값**이다. loss가 낮다고 문장 전체가 사실이라는 보장은 없다.

## 🔁 학습은 어떻게 진행되나

```
입력·정답 → 예측·loss 계산 → 기울기 계산 → 가중치 갱신
```

이 루프를 반복해서 가중치(파라미터)를 목적 데이터에 맞게 조금씩 조정하는 게 파인튜닝이다.

**보충: 기울기 누적(Gradient Accumulation)**
GPU 메모리가 작아서 한 번에 큰 배치를 못 올릴 때 쓴다. 루프 자체는 그대로고, **여러 미니배치의 기울기를 모아서 한 번만 갱신**한다. 예를 들어 미니배치 8개를 누적한 뒤 optimizer step을 1번 하면 더 큰 배치를 쓴 것과 비슷한 효과가 난다.

## ✂️ 데이터를 왜 나눌까 (Train / Validation / Test)

시험 문제로 공부하면 시험 점수는 의미가 없다. 그래서 데이터를 나눈다. 목적은 **암기(과적합)를 탐지**하는 것이다.

| 몫 | 역할 |
|---|---|
| Train | 파라미터를 갱신하는 데 쓰는 데이터 |
| Validation | 학습 중 설정 선택, 과적합 감시용. 반복 사용되므로 **최종 점수는 아님** |
| Test | 최종 1회 평가. 학습·튜닝 중에는 보지 않음 |

예시 비율은 train 600 / validation 100 / test 100. 그리고 **같은 원문·같은 고객(group)은 한 몫에만** 넣어야 한다. 안 그러면 비슷한 데이터가 train과 test에 섞여서 점수가 부풀려진다(누수).

## 🔍 validation loss 읽는 법 + 퀴즈

| train loss | validation loss | 해석 |
|---|---|---|
| ↓ | ↓ | 정상 학습 |
| ↓ | ↑ (지속) | **과적합 의심** (암기 중) |
| 둘 다 높음 | | 학습 부족(underfitting) 또는 설정 오류 |

학습 중에는 validation loss로 **진단**하고, 최종 성능은 **test로 확인**한다.

### 📝 퀴즈 ① 과적합 신호는?

> 파인튜닝 중 train loss는 계속 내려가는데, validation loss는 어느 시점 이후 올라간다. 이때 가장 적절한 해석은?

**답: 과적합을 의심한다. 다만 단독 확정 근거는 아니고, 추가 증거와 함께 본다.**

- train은 좋아지는데 validation이 나빠지는 건 **학습 데이터를 외우고 있다**는 신호다.
- 하지만 **한 번의 상승으로 확정하지 않는다.** 상승이 **지속**되는지 추세를 보고, 다른 평가 질문에서도 같은 패턴이 반복되는지 같은 추가 근거를 함께 확인한다.
- "둘 다 높다"는 과적합이 아니라 학습 부족이나 설정 오류 쪽이다.

## 🔤 토큰과 다음 토큰 예측

**토큰**은 모델이 읽는 단위다. 텍스트 → 토크나이저 → 정수 ID 열 순서로 변환된다.

- 단어·부분 문자열 등 **모델별 처리 단위**(BPE 계열)라서 반드시 단어의 일부는 아니다.
- 모델마다 토크나이저가 달라서 **같은 문장도 토큰 수가 다르다.** 길이는 학습에 쓸 토크나이저 기준으로 잰다.
- **시퀀스 길이 512 = 문자 수가 아니라 토큰 수**다. 상한을 넘으면 뒤가 잘려서, 정답 응답의 일부가 사라질 수 있다.

**다음 토큰 예측(Next Token Prediction)**
SFT에서는 목표 응답의 각 위치마다 "다음 정답 토큰"을 맞히도록 loss를 계산한다.

| 위치 | 앞 토큰 | 정답 다음 토큰 |
|---|---|---|
| 1 | [질문] | 불편 |
| 2 | [질문] 불편 | 을 |
| 3 | [질문] 불편을 | 드려 |
| 4 | [질문] 불편을 드려 | 죄송 |

모든 위치의 loss를 평균내므로 **정답 토큰 확률을 높이는 방향 = loss를 낮추는 방향**이다. 그리고 사전학습도 SFT도 **같은 다음 토큰 예측 loss**를 쓰고, 달라지는 건 데이터다. (사후학습에는 RL 등 다른 목적도 쓴다.)

**자기회귀 생성**: 추론할 때는 프롬프트 전체를 먼저 읽고(prefill) → 토큰 하나 생성 → 입력에 붙여 다시 예측, 를 반복한다. 정해진 정답을 검색하는 게 아니라 **확률 분포에서 선택**한다. 그래서 생성 길이만큼 시간이 걸리고, 파인튜닝으로 형식·톤이 달라져도 이 생성 방식 자체는 그대로다.

## 🎛️ 디코딩 옵션

같은 모델이라도 디코딩 설정이 다르면 출력이 달라진다. 그래서 **모델을 비교할 때는 같은 디코딩 설정**을 써야 한다. 설정이 다르면 차이를 모델 탓으로 해석할 수 없다.

| 옵션 | 의미 |
|---|---|
| greedy (`do_sample=False`) | 매번 최고 확률 토큰 선택. temperature=0이 정의가 아님 |
| `max_new_tokens` | 생성 길이 상한. 상한에서 끝났는지 여부를 기록 |
| `temperature` | 분포를 평평하게(↑)/뾰족하게(↓) 한 뒤 샘플링 |
| `top_p` · `top_k` | 후보 토큰 범위 제한 |
| `repetition_penalty` | 반복 억제 |

## 🛠️ 헷갈렸던 부분

**1) loss가 낮으면 좋은 모델인가?**
→ 아니다. loss는 다음 토큰을 얼마나 잘 맞히는지의 값이지, 사실성이나 정답률 점수가 아니다.

**2) validation과 test는 뭐가 다른가?**
→ validation은 학습 중 설정을 고르려고 **반복해서 보는** 데이터라 점수가 점점 낙관적이 된다. test는 **마지막에 한 번**만 본다.

**3) 시퀀스 길이 512면 글자 512개인가?**
→ 아니다, 토큰 512개다. 한국어는 모델에 따라 글자보다 토큰이 더 많이 나올 수도 있어서 학습에 쓸 토크나이저로 직접 재봐야 한다.

## 💡 정리하면

| 개념 | 한 줄 요약 |
|---|---|
| 파인튜닝 | 사전학습 모델을 목적 데이터로 추가 학습 |
| Loss | 정답 토큰 확률이 낮을수록 커지는 값 (사실성 점수 아님) |
| Gradient Accumulation | 작은 배치 기울기를 모아 한 번에 갱신 |
| Train/Val/Test | 갱신용 / 설정 선택·과적합 감시용 / 최종 1회 평가 |
| 과적합 신호 | train↓ + validation↑ 지속. 단독 확정 X |
| 토큰 | 모델이 읽는 단위. 시퀀스 길이는 토큰 수 기준 |
| 디코딩 | 모델 비교 시 같은 설정으로 고정 |

- 학습 = **loss를 줄이는 방향으로 가중치를 조금씩 수정**하는 반복이다.
- 과적합은 **validation loss의 추세**로 의심하고, 추가 증거로 확인한다.
- 다음 글에서는 가중치를 **전부** 바꾸는지 **일부만** 바꾸는지(Full FT vs LoRA)를 정리한다.
