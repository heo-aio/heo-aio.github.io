## 📱 미디어쿼리란

미디어쿼리는 **PC뿐만 아니라 모바일, 태블릿 등 다양한 화면 크기에 대응**하기 위해 사용하는 CSS 구문이다. 하나의 HTML을 두고, 화면 가로폭(width)에 따라 다른 CSS를 적용해서 반응형(또는 적응형) 웹사이트를 만들 수 있게 해준다.

![PC, 태블릿, 모바일 화면 크기에 따라 다른 레이아웃이 적용되는 미디어쿼리 개념도](/images/html_css/media-query-concept.png)

```css
.media {
    width: 500px;
    height: 500px;
    background-color: red;
}

/* 미디어쿼리 */
@media (min-width: 320px) and (max-width: 800px) {
    .media {
        width: 300px;
        height: 300px;
        background-color: yellow;
    }
}
```

- `min-width`, `max-width`로 **브라우저 가로폭 범위**를 지정한다
- 브라우저 가로폭이 320px ~ 800px 사이에 들어오면, 중괄호 안의 CSS 속성으로 **원래 스타일을 덮어쓴다**
- 즉 평소엔 `.media`가 500×500 빨간 박스지만, 화면이 좁아지면 300×300 노란 박스로 바뀐다

여기서 처음에 헷갈렸던 포인트: 미디어쿼리는 "화면 크기별로 완전히 새로운 CSS를 만드는 것"이 아니라, **기존 CSS 위에 조건부로 덮어쓰는 것**이라는 점이다. 이 관점으로 보니 뒤에 나오는 상속 이야기도 자연스럽게 이해가 됐다.

> ✅ **핵심**: 미디어쿼리는 지정한 화면 가로폭 범위에서만 **기존 스타일을 덮어쓰는** CSS 블록이다.

## ⚠️ 미디어쿼리 사용 시 주의사항
      
### Point I. viewport 메타 태그

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

![viewport 메타 태그가 없을 때와 있을 때 모바일 화면 렌더링 차이 비교](/images/html_css/viewport-meta-tag.png)

- `viewport`는 디지털 기기 화면에 실제로 표시되는 영역(너비·배율)을 설정하는 메타 태그
- 이걸 안 넣으면 모바일 브라우저가 "PC 화면을 축소해서 보여주는 방식"으로 렌더링하려고 해서, 미디어쿼리가 있어도 **의도한 대로 작동하지 않을 수 있다**
- `width=device-width` → viewport 가로폭을 디바이스 실제 가로폭과 동일하게 맞춤
- `initial-scale=1.0` → 처음 로드될 때 배율을 항상 1.0으로 고정

오타 조심할 부분: 메타 태그 속성은 `name="viewport"`처럼 등호(`=`)를 써야 하는데, 강의 노트나 필기하다 보면 `name-"viewport"`처럼 하이픈으로 잘못 적기 쉽다. 이 글에서는 정확한 문법(`name="viewport"`)으로 정리해둔다.

> ✅ **핵심**: `viewport` 메타 태그를 먼저 세팅해야 미디어쿼리가 모바일에서 의도대로 작동한다.

### Point II. CSS 속성 상속

```css
.media {
    width: 500px;
    height: 500px;
    background-color: yellow;
}

@media (min-width: 320px) and (max-width: 800px) {
    .media {
        width: 300px;
        height: 300px;
        background-color: none;
    }
}
```

- 미디어쿼리 **내부**에서 언급하지 않은 속성은 **외부(기본) 스타일을 그대로 상속**받는다
- 위 예시에서 `background-color`를 `none`으로 준 건, "상속받지 않고 초기화하고 싶다"는 의도를 표현한 것

이 부분이 오늘 가장 "아하" 했던 지점이다. 처음엔 미디어쿼리 블록 안에 있는 CSS가 그 조건에서 "전부"라고 착각했는데, 실제로는 **원래 스타일 + 미디어쿼리로 바뀐 부분**이 합쳐진 결과라는 거였다. 그래서 미디어쿼리 안에 `width`, `height`만 써도 `background-color`는 알아서 원래 값을 유지한다.

> ✅ **핵심**: 미디어쿼리 블록에 쓰지 않은 속성은 **외부 스타일에서 그대로 상속**된다. 상속을 끊고 싶으면 명시적으로 값을 다시 지정해야 한다.

## 🛠️ 미디어쿼리 실전 적용 (PC → 모바일)
    
이제 실제로 PC 버전 레이아웃을 모바일(320px ~ 820px 구간)에 맞게 바꿔본 부분이다. 상단 → 본문 → 하단 순서로 하나씩 덮어썼다.

![PC 레이아웃과 미디어쿼리가 적용된 모바일 레이아웃을 나란히 비교한 그림](/images/html_css/media-query-responsive-example.png)

### Point I. 상단(header/intro) 영역

```css
@media (min-width: 320px) and (max-width: 820px) {
    .container {
        width: 640px;
    }

    #intro {
        height: 160px;
    }
    #intro h1 {
        width: 100%;
    }
    #intro nav {
        width: 100%;
    }
    #intro h1 a {
        text-align: center;
        padding: 22px 0 0 0;
    }
}
```

- `.container`의 고정 너비를 좁혀서 모바일 화면 안에 들어오게 만듦
- `h1`, `nav`의 `width`를 `100%`로 바꿔서 **좁아진 화면 폭에 맞게 꽉 차도록** 조정
- `text-align: center`로 로고/타이틀을 가운데 정렬해서 좁은 화면에서도 균형 잡히게 함

### Point II. 본문(main article) 영역

```css
@media (min-width: 320px) and (max-width: 820px) {
    ...

    #main article {
        width: 100%;
        height: 420px;
    }
}
```

- PC에서는 여러 컬럼으로 나뉘어 있을 `article`을 `width: 100%`로 바꿔서 **한 줄에 하나씩 세로로 쌓이는 구조**로 전환
- `height`를 재조정해서 콘텐츠가 좁은 화면에서도 잘리지 않게 함

### Point III. 하단(footer) 영역

```css
@media (min-width: 320px) and (max-width: 820px) {
    ...

    #footer {
        padding: 30px 0;
    }

    #footer .copyright,
    #footer .address {
        width: 100%;
    }

    #footer .copyright p,
    #footer .addres p {
        text-align: center;
        padding: 0;
    }
    #footer .addres p {
        padding-top: 20px;
    }
}
```

- `.copyright`, `.address`도 마찬가지로 `width: 100%`로 세로 스택 구조로 변경
- 텍스트를 `text-align: center`로 정렬해서 좁은 화면에서 어색하게 왼쪽에 쏠리는 걸 방지
- `.addres p`(원문 그대로, `.address`의 오타로 보이지만 실습 코드에 있던 클래스명이라 그대로 남겨둠)에만 `padding-top`을 줘서 두 문단 사이 간격을 확보

세 영역을 다 보고 나니 패턴이 보였다. **PC에서 가로로 나열되던 요소들을, 모바일에서는 `width: 100%` + `text-align: center` 조합으로 세로 스택 + 중앙 정렬로 바꾸는 게 반복되는 흐름**이었다.

> ✅ **핵심**: 모바일 대응은 결국 "가로 배치 → `width: 100%`로 세로 스택" + "정렬 재조정"의 반복 패턴이다.

## 🤔 감이 안 왔던 부분, 다시 짚어보기

처음 미디어쿼리를 봤을 때 "복잡하진 않은데 감이 안 온다"고 느낀 이유를 곰곰이 생각해보니, **문법은 이해했지만 "왜 이 값들을 이렇게 정했는지"의 기준이 없었기 때문**인 것 같다. 예를 들어:

- 왜 `min-width: 320px`인가? → 320px은 예전 아이폰 등 흔히 기준으로 삼는 최소 모바일 가로폭이라 관용적으로 많이 쓰는 값이다
- 왜 `max-width: 820px`인가? → 이 프로젝트에서는 태블릿까지 포함해서 "이 폭 이하면 모바일용 레이아웃을 쓰겠다"는 기준선을 820px로 잡은 것
- 브레이크포인트(breakpoint, 미디어쿼리가 걸리는 기준 폭)는 정답이 정해진 게 아니라 **디자인·콘텐츠에 맞춰 프로젝트마다 정하는 값**이라는 걸 알고 나니 마음이 조금 편해졌다

즉 미디어쿼리 문법 자체보다, **"어느 폭에서 레이아웃이 깨지기 시작하는가"를 직접 눈으로 확인하고 그 지점을 브레이크포인트로 잡는 감각**이 진짜 실력인 것 같다. 이건 문법 암기가 아니라 여러 화면 크기로 직접 늘였다 줄였다 하면서 쌓아야 하는 감각이라, 다음 실습부터는 브라우저 개발자도구로 화면 폭을 실제로 조절해가면서 "여기서부터 어색해지네" 하는 지점을 찾아보는 연습을 해야겠다.

## 💡 정리하면

오늘 배운 걸 한 줄로 정리하면, 미디어쿼리는 **"특정 화면 폭 구간에서 기존 CSS 위에 조건부로 스타일을 덮어쓰는 것"**이고, 그 안에서 안 건드린 속성은 그대로 상속된다는 것. 그리고 실전 적용에서는 결국 가로 배치 요소를 `width: 100%`로 풀어서 세로로 쌓는 패턴이 반복된다는 것도 확인했다.

**오늘의 핵심 4가지**

- 📱 미디어쿼리는 지정 폭 구간에서 **기존 스타일을 덮어쓰는** 조건부 CSS다
- ⚠️ `viewport` 메타 태그 없이는 모바일에서 미디어쿼리가 의도대로 안 먹을 수 있다
- 🌊 미디어쿼리 안에서 안 쓴 속성은 **외부 스타일을 그대로 상속**받는다 (끊고 싶으면 명시적으로 재지정)
- 🛠️ 모바일 대응은 대부분 "가로 배치 → `width: 100%` 세로 스택 + 정렬 재조정" 패턴의 반복이다

**다음에 실전 적용할 것**

1. 미디어쿼리 붙이기 전에 → 항상 `viewport` 메타 태그부터 확인
2. 상속시킬 속성 / 초기화할 속성을 미리 구분해서 → 미디어쿼리 블록을 최소한으로 작성
3. 브레이크포인트는 암기하지 말고 → 개발자도구로 화면 폭을 직접 조절하며 "깨지는 지점" 찾는 연습하기
