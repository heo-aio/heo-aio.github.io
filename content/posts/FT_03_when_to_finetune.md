파인튜닝 정리 시리즈 마지막 글이다. 결국 제일 중요한 질문은 **"파인튜닝을 언제 하나?"**였다. 퀴즈 3문제도 여기에 걸려 있어서 함께 정리했다.

## 목차
- 🪜 LLM이 만들어지는 흐름 (Pre-training → SFT → 정렬)

- 🔎 RAG 실패는 세 곳으로 나눠 진단
- 🧭 파인튜닝 전에 먼저 물어볼 것 + 퀴즈 ③

- 🛠️ 헷갈렸던 부분

## 🪜 LLM이 만들어지는 흐름

| 단계 | 내용 |
|---|---|
| Pre-training | 넓은 텍스트 분포로 다음 토큰 예측. 언어·지식 습득, 대규모 GPU·장기간 |
| SFT | 지시-응답 예시로 학습. "질문에 답하는 형식" 습득 |
| 선호 최적화(정렬) | 비교·보상 정보 활용(RLHF, DPO). 더 도움 되고 덜 해로운 답 |
| 실무 파인튜닝 | 공개 Instruct 모델에 **목적별 추가 학습** (2·3단계를 자기 데이터로 소량·짧게) |

모든 모델에 필수인 동일 공정은 아니다. 그리고 실무에서는 사전학습부터 새로 만들지 않고 **공개 가중치에서 시작**한다.

| | Pre-training | SFT |
|---|---|---|
| 데이터 | 웹·책·코드 등 일반 텍스트 (대형 모델은 수조 토큰) | 목적 지시-응답 데이터 (실무는 보통 수백~수만 건) |
| 목적 | 언어·세계 지식 | 형식·행동·도메인 말투 |
| 시작점 | 무작위 초기화 | 사전학습 파라미터 |

공개 보고서 예시로 Qwen2.5는 사전학습 18조 토큰, SFT 100만 건 이상이고, LIMA는 SFT 1,000건으로 실험했다. 지식은 대부분 사전학습에서 습득된다는 주장(LIMA)과도 이어진다.

## 💬 In-Context Learning(ICL): 가중치 없이 행동 바꾸기

**가중치는 그대로 두고 입력 안의 지시·예시만으로** 원하는 형태를 유도하는 방법이다. 예시 없이 지시만 주면 zero-shot, 예시를 몇 개 넣으면 few-shot이다.

- 잘 되는 것: 출력 형식 지정(JSON·표), 말투·길이 조정, 간단한 분류·추출
- 안 되는 것: 예시가 늘면 컨텍스트 길이·비용 증가, 요청마다 일관성 흔들림, 복잡한 규칙은 예시로 다 못 보임
- 한계 신호: 프롬프트가 수백 줄로 자라는데도 실패율이 안 떨어짐

그래도 **파인튜닝 전 첫 시도는 항상 ICL(프롬프트 기준선)**이다. 파인튜닝 효과는 이 기준선과 비교해서 평가한다.

프롬프트는 네 요소로 구성한다.

| 역할 | 지시 | 예시 | 출력 형식 |
|---|---|---|---|
| 어떤 관점으로 답할지 | 어떤 일을 수행할지 | 원하는 답의 사례 | 답변의 구조와 길이 |

## 💸 ICL · RAG · FT 비용 구조

| | ICL | RAG | FT |
|---|---|---|---|
| 준비 비용 | 프롬프트 작성 | 문서 색인·검색기 | 데이터 제작 + 학습 GPU |
| 요청당 비용 | 예시 토큰 반복 | 검색 + 긴 컨텍스트 | 짧은 프롬프트, 자체 서빙 |
| 바꿀 수 있는 것 | 형식·말투(약하게) | 참조 지식·출처 | 행동·형식·말투(강하게) |
| 갱신 | 즉시 | 문서 교체 즉시 | 재학습 필요 |
| 위험 | 일관성 | 검색 실패·문서 활용 실패 | 과적합·퇴화 |

## 🔎 RAG 실패는 세 곳으로 나눠 진단

RAG로 근거를 찾아줘도 실패가 남을 수 있다. **어디서 틀렸는지 나눠서** 본다.

1. **검색 실패**: 필요한 근거 문서를 못 찾음
2. **근거 활용 실패**: 문서는 찾았는데 모델이 그걸 제대로 못 씀
3. **형식·말투·절차 규칙 실패**: 정해진 답변 규칙을 못 지킴

수업 예시: "주문번호 ○○, 지금 취소할 수 있나요?" 질문에 검색된 근거는 "출고 전 주문은 취소 가능, 출고 후에는 반품 접수로 안내"였고 규칙은 "존댓말 두 문장, 출고 여부를 먼저 확인"이었다. 그런데 모델이 "바로 취소해 드렸어요!"라고 답했다. 진단하면

- 검색 실패? → 아니오 (근거 문서는 찾음)
- 근거 활용 실패? → 예 (출고 전만 가능한데 근거 없이 취소 완료로 단정)
- 규칙 실패? → 말투는 OK, **출고 여부 확인 절차는 누락**

이 사례 하나로 파인튜닝이 필요하다고 판단하지 않는다. 먼저 근거 배치·확인 절차를 **프롬프트(지시·예시)로 고쳐서 평가셋으로 재평가**하고, 기준선에서도 실패가 반복될 때 FT를 검토한다. (이 사례는 설명용이고 실제 실행 결과가 아니다.)

## 🧭 파인튜닝 전에 먼저 물어볼 것

```
프롬프트로 목표를 충족하는가?        → 예: 프롬프트 기준선 유지
  ↓ 아니오
주된 부족이 지식·최신 정보인가?      → 예: RAG 보완 후 다시 평가
  ↓ 아니오 (행동·형식 문제)
정답 데이터·평가·운영 준비 확인       → SFT 후보 검토
```

SFT 판단 흐름은 이렇다.

| 체크 | 아니오면 |
|---|---|
| 정답 응답 데이터가 준비됐는가? | 데이터 수집·정제 후 재검토 |
| 기준선과 평가셋이 준비됐는가? | 프롬프트 기준선·평가셋 준비 |
| 학습·운영 자원이 준비됐는가? | 모델 크기·기법·자원 재검토 |
| 모두 예 | SFT 학습 후 기준선과 비교 평가 |

지식과 행동 문제가 같이 있으면 RAG 보완과 행동 평가를 함께 간다. 정답 데이터 부족은 SFT 준비 단계로 연결된다.

**데이터가 적을 때 먼저 볼 것**: 품질(오탈자·형식 불일치 정제), 다양성(표현·사례가 한쪽으로 쏠리지 않는지), 평가셋(학습에 안 쓴 별도 문제). "100건"은 설명을 돕는 휴리스틱이지 학습 가능 여부의 절대 경계가 아니다. 소량 데이터로 학습한 연구 사례도 있지만 안정적 개선이 보장되는 건 아니라서 평가로 확인한다. 또 **반복 학습이 새로운 사례를 만들어 주지는 않는다.**

### 📝 퀴즈 ③ RAG는 되는데 응답 형식 규칙이 불안정하다면?

> RAG로 근거 문서는 잘 찾아오는데, 정해 둔 응답 형식 규칙을 일관되게 못 지킨다. 다음 행동으로 가장 적절한 것은?

**답: 정답 데이터, 평가셋, 학습 자원이 준비돼 있는지 점검하고 SFT를 검토한다.**

- 문제의 성격이 **지식 부족이 아니라 행동·형식**이다. 그러니 문서를 더 넣는 건 맞지 않다.
- 프롬프트 예시를 더 넣는 것은 비용·일관성 한계가 있다. (물론 이미 기준선에서 시도해 봤다는 전제다.)
- 더 큰 모델로 바꾸는 것만으로 해결된다는 보장이 없다.
- 그래서 **정답 데이터 → 평가셋 → 학습 자원** 순서로 준비 상태를 확인하고 SFT 후보로 올린다.

## 🎯 파인튜닝으로 바꾸기 쉬운 것 / 어려운 것

| 구분 | 내용 | 조건·근거 |
|---|---|---|
| 잘 바뀜 | 출력 형식, 말투·길이, 도구 호출 규칙, 과제 수행 방식 | 목표 행동을 보여 주는 정답 데이터가 있고 평가로 개선을 확인할 때 |
| 잘 안 바뀜 | 사전학습에 없던 **새 사실 지식** | 파인튜닝으로 새 사실을 익히기 어렵고, 억지로 학습하면 환각 경향이 늘 수 있다는 연구(Gekhman et al., 2024). 최신·사내 지식은 RAG로 |
| 부작용 | 좁게 학습하면 다른 과제 성능 저하 (Catastrophic Forgetting) | 정도는 기법·데이터·학습량에 따라 다름 |
| 소량·짧은 학습 | 개선이 없거나 오히려 나빠질 수 있음 | 학습 전 기준선과 같은 평가셋·일반 과제로 비교해 판단 |

### 📝 퀴즈 ④ 파인튜닝으로 무엇을 기대할 수 있나?

> 파인튜닝에 대한 설명으로 가장 적절한 것은?

**답: 응답 형식·톤·행동은 비교적 잘 바꾸지만, 새로운 사실 지식을 넣는 데는 약하고 오히려 환각이 늘 수도 있다. 최신 사실은 RAG가 낫다.**

- "파인튜닝하면 새 지식이 다 들어간다"는 흔한 오해다.
- 형식·톤·행동은 데이터로 잘 바뀐다.
- 새 사실은 잘 안 익고, 억지로 학습시키면 환각 경향이 커질 수 있다.
- 그래서 **행동은 FT, 지식은 RAG**로 역할을 나누는 게 기본이다.

**RAG와 FT의 역할 분담 예시**

| 서비스 | RAG 역할 | SFT 역할 |
|---|---|---|
| 고객상담 | 정책 조회 | 상담 응답 형식 학습 |
| 사내 도구 에이전트 | 검색 정보 제공 | 도구 호출 규칙 학습 |
| 법률·의료 문서 | 전문 정보 검색 | 출력 형식 설계·학습 |

추론 때는 질문 → 검색기가 근거 제공 → FT한 생성 모델이 근거를 읽고 답변하고, 학습 때는 우리 응답·도구 호출 예시로 SFT한다. 경계가 절대적인 건 아니고 형식 준수는 별도로 평가한다. 공통으로 **보지 못한 질문에서 근거 사용·형식 준수**를 평가한다.

## ⚠️ 실패 사례: 과적합 vs 망각

**과적합 사례**: 학습 데이터에 "배송이 너무 늦어요 → 불편을 드려 죄송합니다. 주문번호를 알려주시겠어요?"가 있었다. 그런데 평가에서 **주문번호가 이미 포함된 질문**에도 같은 문장으로 번호를 다시 요청했다. 받은 정보를 무시하고 학습 문장을 그대로 반복한 것이라 과적합이 의심된다. (실제 실행 결과가 아닌 예시)

- 단일 사례로 확정하지 않고, validation loss 상승·다른 평가 질문에서의 반복 같은 **추가 근거를 함께 확인**한다.
- 원인 후보: 데이터 대비 **과한 반복 학습(epoch)**, 비슷한 문장의 **데이터 중복**. (큰 학습률, 고정 epoch 수가 보편적 해법은 아니다.)

**커버리지 부족 사례**: 학습 데이터에 주문 조회는 있는데 **취소·환불 안내는 없는** 경우다.

| 업무 유형 | 학습 데이터 | 후속 조치 |
|---|---|---|
| 주문 조회 | 포함 | 표현·조건 다양성 확인 |
| 주문 취소 | 미포함 | 정답 응답 보완 |
| 환불 안내 | 미포함 | 정책·예외 사례 보완 |

"취소하고 싶어요"에 "배송 조회는 마이페이지에서 확인하세요"라고 답했다면 취소 요청과 무관한 응답이다. 취소 문의-응답 쌍을 학습 데이터에 추가하고, 새 평가 질문으로 재평가한다. 미포함 유형은 **별도 평가**로 확인한다.

### 📝 퀴즈 ⑤ 과적합과 Catastrophic Forgetting은 같은 말일까?

> 파인튜닝 후 모델이 이상해졌다. 과적합과 Catastrophic Forgetting에 대한 설명으로 맞는 것은?

**답: 둘은 서로 다른 현상이다. 함께 나타날 수 있지만 원인과 해석이 달라서 따로 진단한다.**

| | 과적합 (Overfitting) | Catastrophic Forgetting |
|---|---|---|
| 무슨 일 | 학습 데이터의 암기·노이즈에 맞춰져 **일반화**가 떨어짐 | 파인튜닝하면서 **기존에 잘하던 능력**을 잃음 |
| 진단 | train vs validation loss 차이, 새 질문에서 반복·실패 | 학습 전 기준선과 **같은 평가셋·일반 과제**로 비교 |

- 둘이 동시에 보일 수도 있지만, "과적합 = 망각"이 아니다.
- 이 때문에 파인튜닝 전에 **기준선 점수를 미리 저장**해 두는 게 중요하다.

## 📚 사례 모음

**InstructGPT (Instruction tuning)**: SFT → 보상모델(응답 선호 순위 학습) → PPO(보상을 높이는 정책 학습)의 3단계로 SFT와 사람 선호 학습을 결합한 공개 연구다. 연구의 프롬프트 분포에서 사람 평가 결과 1.3B InstructGPT 응답이 175B GPT-3보다 선호됐다. 단, SFT+RLHF의 결합 결과이고 한국어 상담 성능으로 일반화할 수는 없다.

**Base vs Instruct 모델**: 서로 다른 체크포인트(예: Qwen2.5-1.5B vs Instruct)의 출력 차이는 **사후학습과 입력 형식(chat template)의 영향이 함께** 섞여 있다. 그래서 그 차이를 SFT만의 효과로 분리할 수 없고, 순수 인과 실험도 아니다.

**CUAD (법률문서 분석 연구)**: 계약서에서 조항 구간을 추출하고 41개 범주로 분류하는 과제다. 전문가가 주석한 계약서 510개, 조항 주석 13,101개로, 사전학습 NLP 모델(BERT·RoBERTa·DeBERTa 계열)을 구간 추출 QA로 파인튜닝했다. 같은 데이터에 학습한 **모델 간 비교**이지 같은 모델의 FT 전후 비교가 아니다. 한국법·법률 의견 생성이나 상용 운영 성능을 검증한 것도 아니다.

## 🛠️ 헷갈렸던 부분

**1) 파인튜닝하면 우리 회사 문서를 학습시킬 수 있지 않나?**
→ 새 사실을 넣는 용도로는 약하다. 사내·최신 지식은 RAG로 근거를 주고, 파인튜닝은 **답하는 방식**을 맞추는 데 쓴다.

**2) 프롬프트와 RAG로 안 되면 바로 파인튜닝?**
→ 실패를 먼저 검색 / 근거 활용 / 형식·절차로 **나눠 진단**하고, 프롬프트 기준선에서도 남는 실패일 때 검토한다. 그리고 정답 데이터·평가셋·자원이 준비돼야 한다.

**3) 데이터가 100건 미만이면 못 하나?**
→ 절대 기준은 아니다. 품질·다양성·평가셋을 같이 보고, 효과는 평가로 확인한다.

## 💡 정리하면

| 개념 | 한 줄 요약 |
|---|---|
| ICL | 가중치 변경 없이 지시·예시로 행동 유도. 파인튜닝 전 첫 시도(기준선) |
| RAG | 최신·사내 지식을 근거로 제공 (가중치는 안 바뀜) |
| FT/SFT | 형식·말투·도구 호출 같은 행동을 강하게 고정 |
| 새 사실 지식 | FT로 넣기 어렵고 환각 위험 → RAG |
| 진단 순서 | 검색 실패 → 근거 활용 실패 → 형식·절차 실패 |
| 과적합 ≠ 망각 | 둘은 다른 현상. 따로 진단 |

- 선택 순서는 **프롬프트 기준선 → (지식이면) RAG → (행동·형식이면) 데이터·평가·자원 점검 후 SFT**다.
- 파인튜닝의 성패는 학습보다 **데이터와 평가셋 준비**에서 갈린다.
- 어떤 선택이든 마지막은 **같은 평가셋으로 기준선과 비교**하는 것이다.
